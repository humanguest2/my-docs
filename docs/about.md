# 关于本项目

## 项目目标

实现从 Markdown 文档到公开网站的自动化发布。

具体来说，我希望做到三件事：内容只写一次（Markdown），发布不用手动操作（推送即部署），地址长期固定（Pages 提供）。这样维护文档的成本就落在“写”这一件事上，而不是消耗在打包和上传上。

## 技术组成

| 工具 | 作用 |
| --- | --- |
| Markdown | 编写文档内容 |
| MkDocs Material | 将文档构建成静态网站 |
| GitHub Actions | 自动执行安装、构建和部署 |
| GitHub Pages | 托管并提供网站访问地址 |

## 我对这几个工具关系的理解

这四个工具是流水线上的四道工序，顺序不能颠倒。Markdown 是原料，MkDocs 是加工机器，`site/` 是加工出来的成品，Actions 是自动按下机器开关的工人，Pages 则是把成品摆在橱窗里给人看的展台。

我一开始以为 `site/` 也应该提交到仓库里，后来才明白它是**产物**而不是**源码**：只要源码和配置还在，随时能重新生成同样的 `site/`；反过来，把产物提交进仓库，每次构建都会产生大量无意义的差异，还容易和源码不同步。所以 `.gitignore` 里写了 `site/`。
